What VaultSeek does

VaultSeek is a Windows desktop app for a personal music collection. It watches a drop folder, identifies songs, organizes them into a tidy Library, and can search download sources for missing tracks or better-quality copies.

Think of it in two halves:

  1. Library work — scan Incoming, fingerprint, identify, review, organize, artwork, media-server refresh.
  2. Acquisition — find gaps, queue a Wishlist, search sources, download, verify, then import back into Incoming.

VaultSeek does not replace Soulseek, Prowlarr, qBittorrent, or SABnzbd. Those programs do the actual searching and downloading. VaultSeek talks to them and then treats the finished files like anything else you dropped in Incoming.

First run

The first time you start VaultSeek with no library, the Setup wizard opens. You can reopen it anytime from Help → Setup wizard… or the Dashboard button.

The wizard asks for:

  • A library name, plus Incoming and Library folders (Staging and Archive are optional and filled in as siblings if you leave them blank).
  • Optional Nicotine+ connection (Soulseek downloads).
  • Optional Discogs and AcoustID keys (better identification and Discogs browse).
  • A quality preset (what “good enough” means for orange/green row colors and upgrades).

After Finish, follow the Dashboard Getting started checklist: confirm folders, connect a download source if you want one, then Scan Incoming.

Re-running the wizard updates the library currently selected in the top toolbar. It no longer overwrites “the first library only,” and it keeps Nicotine+ transport settings you already saved.

Theme and log level apply as soon as you save preferences. Discogs, AcoustID, Shazamio, and fingerprint mode need a restart of VaultSeek after Save preferences. Prowlarr / qBittorrent / SABnzbd reconnect as soon as you save Plugins.

Incoming, Library, and other folders

Each library is four folders on disk (Settings → Library):

FolderRequired?What it is for
Incoming Yes Drop new files here. Downloads land here after they are verified. Files stay here through identify and review, then move to Library when approved.
Library Yes The organized collection (artist / year – album folders after organize).
Staging No Optional hold folder. If you leave it blank, VaultSeek suggests a sibling named Staging. Everyday use is Incoming → Library.
Archive No Duplicates and rejected files. Blank is filled with a sibling named Archive.

Watch incoming folder — when checked, new files in Incoming start a scan automatically.

Identify auto-approve (0–1, default 0.90) — if identification confidence is at least this high, the track skips Review and can organize straight to Library. This is not the download score (that is Download auto-acquire under Wishlist & downloads).

Day-to-day use

  1. Put audio in Incoming (or let a download finish there).
  2. File → Scan Incoming (or wait if Watch is on). Watch Jobs while hash / fingerprint / identify run.
  3. Open Review if items need a decision. Approve good matches.
  4. Browse Library / Artists / Albums. Green rows meet your quality preset; orange rows are missing or below prefs.
  5. To fill gaps: Find music → Find missing songs (or Discogs browse). Then open Wishlist and Auto-acquire, or pick a result.
  6. Parked Discogs picks sit as Wanted. On Wishlist, enable Show Wanted, then Start Wanted download.

Dashboard

Operations home: pipeline counts, collection totals, wishlist progress, a live log tail, and a Getting started checklist until you dismiss it.

  • Click a KPI card to jump to Jobs, Review, Library, Find music, or Wishlist.
  • Wishlist search cadence is shown as text. Change it in Settings → Wishlist & downloads.
  • The checklist tells you whether Nicotine+ and/or Prowlarr are actually connected — not just enabled.

Library (Files)

Folder tree plus a track table. Colors: green = meets quality prefs; orange = missing file or below your bitrate / lossless prefs.

  • Scan Incoming — queue a scan of this library’s Incoming folder.
  • Find music… — jump to gap scans and Discogs.
  • Right-click a row for Explorer, gap scan, or quality-upgrade scan.

Artists, Albums, Artwork, Duplicates

Artists

Artists created during identify. Select a row for tracks; double-click to open Albums filtered to that artist.

Albums

Album list with cover and tracks. Orange means missing songs or below quality prefs. Right-click to find missing songs for one album or the whole library, or queue a download.

Parked Wanted items are not managed here. Albums shows a count and an Open Wishlist button. Start or remove Wanted items on Wishlist.

Artwork

Cover status (OK / low-res / missing). Covers are fetched by pipeline jobs, not from this page.

Duplicates

Open groups the pipeline detected. A side-by-side compare viewer is not built yet. Possible-duplicate items also appear on Review.

Find music

One place to queue downloads. Two tabs:

Library gaps

  • Find missing songs — compare identified albums to MusicBrainz tracklists and create Wishlist jobs for gaps. Needs MusicBrainz-linked albums (identify first).
  • Find quality upgrades — queue upgrades for tracks below Settings → Library quality.
  • Open wishlist — jump to the download queue.

Discogs browse

Search an artist, browse the discography, then either Queue selected for download (search now) or Add to Wanted (park until you start them on Wishlist). Needs a Discogs token in Settings → Application.

Wishlist

The download queue. Each row is one thing you asked VaultSeek to find (a missing track, a missing album, or a quality upgrade).

Typical job path:

Created → Queued → Searching → Scoring → Downloading → Verifying → Importing → Completed. Other outcomes: No results, Waiting for user, Failed, Cancelled.

Review

Human gate for uncertain identifications and similar problems. Ctrl+Enter approve, Ctrl+Shift+R reject. Approved items continue to organize; rejected items may go to Archive.

How many items land here depends on Identify auto-approve in Settings → Library. Lower = more automatic; higher = more Review.

Jobs, Activity, Reports, Logs

Jobs

The library pipeline queue: scan, hash, fingerprint, identify, organize, artwork, media-server sync. Wishlist downloads are a different queue (see Wishlist). Cancel and retry need a selected row.

Activity

Combined timeline of pipeline jobs and wishlist downloads. Select a row, then Open… to jump to Jobs or Wishlist.

Reports

Session charts of acquisition outcomes, plus “Generate library summary file” into the reports folder.

Logs

Tail of vaultseek.log, plus buttons for debug.log and the crashes folder. Also: File → Open Log Folder.

How a download works

  1. You queue a job — Find missing songs, Discogs, or a manual album queue.
  2. Search — connected sources (Nicotine+, Prowlarr, …) look for the artist / album / track.
  3. Score — hits are ranked by how well they match title, artist, format, and your quality prefs.
  4. Download — if the score is at or above Download auto-acquire, VaultSeek starts the download. Otherwise the job waits for you to pick a result.
  5. Verify — files are never trusted automatically. VaultSeek checks they look like real audio.
  6. Import — verified files are copied into Incoming, then the normal scan → identify → organize path runs.

For missing-track jobs, VaultSeek looks for a whole album first. If no acceptable album pack is found, it falls back to a per-track search using the same quality settings.

Background wishlist searches run on the interval in Settings (0 hours = as often as Soulseek / provider rate limits allow).

Search source order (waterfall)

When more than one download source is enabled, VaultSeek tries them in a list you control. Open Settings → Wishlist & downloads → Search source order, then Save preferences.

Default order:

  1. Nicotine+ (Soulseek)
  2. Usenet (Prowlarr NZBs → SABnzbd)
  3. Prowlarr public torrents → qBittorrent
  4. Prowlarr private torrents → qBittorrent
  • Stop after the first source that finds results (on by default) — later sources are skipped once a connected source returns hits.
  • Wait after an empty source (default 15 seconds) — pause before trying the next tier when the current one found nothing.
  • A Soulseek rate-limit error does not stop later sources.
  • Turn the stop-after-first-hit box off if you want every connected source searched every time.

Enable Prowlarr / SABnzbd / qBittorrent on Plugins. Enable Nicotine+ on Settings. Reorder does not turn sources on.

Soulseek via Nicotine+

VaultSeek does not speak the Soulseek protocol itself. It talks to Nicotine+ running on the same PC.

Recommended: HTTP (api-nicotine-plus)

  1. Install and start Nicotine+. Log into Soulseek and stay connected.
  2. Install the community api-nicotine-plus plugin so Nicotine+ exposes an HTTP API (default port 12339).
  3. In VaultSeek: Settings → Wishlist & downloads.
  4. Check Enable Nicotine+ provider.
  5. Transport: HTTP (api-nicotine-plus). Host usually 127.0.0.1. HTTP API port 12339. Token if your plugin requires one.
  6. Click Test Nicotine+ connection, then Save preferences.

Advanced: NDJSON socket

Use this only if you run VaultSeek’s NDJSON companion proxy (scripts/nicotine_plus_ndjson_proxy.py) on port 22024. Set transport to VaultSeek NDJSON socket and match the NDJSON port. Keep the same HTTP plugin running behind the proxy.

Search rate limits

Soulseek can ban accounts that search too quickly (often about 30 minutes). Defaults are conservative: at least 5 seconds between searches, and at most 8 searches per minute. Raise these only if you know what you are doing.

Nicotine+ must stay running and logged in. If it is closed, Wishlist searches return nothing even when the provider is “enabled” in Settings.

Prowlarr with qBittorrent and/or SABnzbd

Configure this on System → Plugins (not Settings). Prowlarr searches your indexers. VaultSeek then sends the hit to the matching download client.

Ports — avoid a clash

AppTypical URLWhere to copy the key
Prowlarrhttp://127.0.0.1:9696Prowlarr → Settings → General → API Key

SABnzbd often occupies port 8080. VaultSeek defaults qBittorrent to 8081 so the two do not collide. If qBittorrent is still on 8080, VaultSeek may talk to SABnzbd by mistake. Change qBittorrent’s Web UI port, restart it, then paste the same URL in Plugins.

Prowlarr

  1. Add audio indexers in Prowlarr (Torznab and/or Newznab).
  2. Copy the API key.
  3. In VaultSeek Plugins: enable Prowlarr, paste URL and key, set minimum torrent seeders (NZBs ignore seeders).
  4. Click Test Prowlarr.

VaultSeek searches Prowlarr’s Audio category (3000) by default.

qBittorrent (torrents)

  1. Enable the Web UI. Prefer port 8081 if SABnzbd uses 8080.
  2. In Plugins: enable qBittorrent, enter URL, username, password.
  3. Optional category vaultseek keeps VaultSeek torrents easy to spot.
  4. Optional save path; blank uses qBittorrent’s default. VaultSeek reads the completed path from the Web UI.
  5. Click Test qBittorrent.

SABnzbd (Usenet / NZB)

  1. Configure your Usenet server inside SABnzbd first.
  2. Copy the API key from Config → General.
  3. In Plugins: enable SABnzbd, paste URL and key, optional category vaultseek.
  4. Click Test SABnzbd.

When a job completes, VaultSeek imports audio from SABnzbd’s completed-folder path, then runs Incoming as usual.

Save and try one album

  1. Click Save plugin settings.
  2. Find music → queue one album (or promote a Wanted item).
  3. Wishlist → Auto-acquire. Watch the job: Searching → Downloading → Verifying → Completed.
  4. Check Incoming, then Library after organize.

Last.fm and Spotify (suggestions only)

These plugins never download files. They add parked Wishlist entries you can promote later.

Similar music (Last.fm)

  1. Create a free key at last.fm/api/account/create.
  2. Plugins: enable similar-music, paste the key, set how many similar artists and top albums to pull.
  3. Save plugin settings, then Find recommendations now.

Spotify playlist sync

  1. Create an app at developer.spotify.com/dashboard (Web API / Client Credentials).
  2. Paste Client ID and Client secret. Add public playlist URLs, one per line.
  3. Save, then Find recommendations now.
Only public playlists work. VaultSeek does not log you into Spotify. Web API access typically requires Spotify Premium on the account that owns the developer app. A dummy redirect URI such as http://127.0.0.1:8888/callback is often required when creating the app, even though VaultSeek does not use it.

Settings page (every group)

Library

Name and folder paths for the library selected in the top toolbar. New library clears the form so you can add another collection. Scan incoming now queues a scan after the library is saved.

Reset processing

  • Clear job & review queues — deletes pending/running/failed jobs and review items. Catalog tracks and files on disk stay.
  • Clear catalog records — also removes track rows from the database. Files on disk are not deleted. Dashboard totals go back to zero. Re-scan Incoming to rebuild.

Library quality

Drives orange/green colors on Library and Albums, and “Find quality upgrades.” This is not a download-provider setting. See Quality presets.

When upgrading, prefer matching whole-album folders from the same peer — on Soulseek upgrades, prefer a folder that has the rest of the album from the same user.

Application

  • Log level — INFO for everyday use; DEBUG when something fails (applies on Save).
  • Theme — dark or light (applies on Save).
  • Discogs token — personal access token from discogs.com/settings/developers. Improves identify (genre, label, catalog) and enables Discogs browse. Restart after save.
  • AcoustID accounts + Shazamio proxies — up to three application keys (register at acoustid.org/new-applications) and optional HTTP proxies. Each key+IP is limited to about 3 lookups/sec. Proxies are also used by the Shazamio fallback (about 1 request/sec per IP). Restart after save.
  • Fingerprinting — every song, or sample a folder (faster). Sample mode only skips remaining files after enough songs match the same album, tags and filenames look right, and the file count matches the official track list. Needs an AcoustID key. Restart after save.

Open log folder / Open data folder are shortcuts. The full log viewer is System → Logs.

Quality presets

These control traffic-light colors and upgrade scans, and they influence which search hits look “good enough.”

PresetWhat it means
CompletistPrefer lossless (FLAC/ALAC). No minimum bitrate for lossy files.
CollectorPrefer lossless. Lossy must be at least 320 kbps. Suggested on first-run wizard.
Lossy OKAccept good MP3 (prefer MP3, min 192 kbps).
CustomYou edited lossless / codec / bitrate by hand.

Editing the three fields under the preset automatically switches the combo to Custom (or back to a named preset if the values match).

Data and logs

VaultSeek stores its own data under %APPDATA%\VaultSeek\ (not inside your music folders):

  • config.json — settings and API keys. Do not share this file.
  • vaultseek.db — catalog database
  • logs\vaultseek.log — everyday log
  • logs\debug.log — verbose log
  • crashes\ — crash logs if something dies
  • reports\ — generated summary files

Only one VaultSeek window should run at a time (the database is locked).

Help → About shows the exact data and log paths for this install.
