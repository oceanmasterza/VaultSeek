Connect your music tools

VaultSeek coordinates three different jobs: identify audio with metadata services, find and download missing releases with download providers, then refresh your media server after organization. A Discogs or AcoustID key does not download music. Jellyfin plays your collection; it is not a source of missing albums.

  1. In Settings → Library, save your Incoming and Library folders. Keep incomplete downloads outside these folders.
  2. In Plugins → Detect local download clients, VaultSeek reads standard Windows configuration files for Prowlarr, qBittorrent and SABnzbd. Select only the suggestions you want to copy. This replaces the selected form fields, including an existing remote address. It does not save or enable them.
  3. Review the URLs and credentials, test each connection, enable your chosen providers and click Save plugin settings.
  4. Set up Nicotine+ and identification in Settings, then save preferences. Restart for metadata/fingerprinting changes.
  5. Select your library and save its media-server connection. Configure that server to watch the organized Library directory.
  6. Try one known album manually before enabling unattended acquisition. Check download completion, verification, Incoming processing and server visibility.

The Dashboard Music tools panel shows whether Nicotine+, Usenet, Prowlarr torrent tiers, AcoustID, Discogs and a media server are connected, enabled but unreachable, or still off. Use its Settings / Plugins / Setup instructions buttons to finish configuration. The Go to selector stays above Settings and Plugins so you can jump to a section.

Automation boundary: detection reads existing configuration only. It cannot create paid accounts, accept account terms, recover hashed passwords, install Nicotine plugins or enable a disabled Web UI. Portable, container and remote installations need their actual address entered manually. A successful connection test is not proof of indexer coverage, available peers or completed imports.

For one PC, use 127.0.0.1 with each service's configured port. Common examples are Prowlarr 9696, Jellyfin 8096 and Nicotine's HTTP plugin 12339. qBittorrent and SABnzbd can conflict on 8080: give them different ports. Preserve URL prefixes such as /sabnzbd. Local detection uses saved values, which may differ from a running process until it restarts.

Fingerprinting, registration and multiple connections

Chromaprint/fpcalc computes an audio signature locally. AcoustID matches it to MusicBrainz recordings; MusicBrainz supplies release metadata. Fingerprints identify recordings, not the mastering quality or authenticity of a claimed high-resolution file.

  1. Use the bundled fpcalc executable. If missing, install Chromaprint's fpcalc from its official release and set FPCALC to its full executable path before starting VaultSeek. See Chromaprint.
  2. Open AcoustID application registration, sign in through the offered login method and register your application.
  3. Copy the application key into Settings → Application → AcoustID. The user key for fingerprint submissions is a different credential.
  4. Give it a recognizable label. Leave Proxy blank for normal direct access.
  5. For additional authorized credentials, choose Add another account / connection, enter a label and key in each row. Clear both key and proxy to remove a connection when saving. Existing additional rows are preserved.
  6. Save preferences and restart. Scan a known, tagged audio file and inspect Jobs/Activity. A valid key can still return no match for an unknown recording.

Do not assume extra accounts or proxies increase your allowance. Follow the service's usage terms and request approval for higher traffic. AcoustID API documentation.

Shazamio is a community audio-recognition fallback; this version has no Shazam account or developer-key field. It uses direct access and optional configured proxy routes. Service changes can break it. Proxy URLs may include credentials, so the form masks them. Use only a proxy you trust.

Performance choice: Fingerprint every song is the most thorough. Sample album folders reduces work by trusting remaining siblings after enough tracks match. Use sampling only for consistently tagged album folders; mixed compilations and uncertain files deserve individual identification. Increasing worker counts does not remove external service rate limits.

Discogs: metadata and artwork

  1. Create or sign into your Discogs account and finish any email verification.
  2. Open Settings → Developers and generate a personal access token. This is separate from your password and two-factor authentication code.
  3. Paste it into Settings → Application → Discogs token. Save preferences and restart VaultSeek.
  4. Search a known artist on the Discogs page. If access fails, check that the token is current and copied completely; regenerate it if revoked.

Discogs helps distinguish editions, catalog numbers, artwork and tracklists. VaultSeek currently stores one Discogs token. Its marketplace sells physical releases; the metadata API does not supply downloadable music files.

Nicotine+, Prowlarr, qBittorrent and SABnzbd

Nicotine+ / Soulseek

  1. Install Nicotine+, set up your Soulseek login in its own settings and connect. First confirm that a normal search works inside Nicotine+.
  2. Install the community api-nicotine-plus plugin into Nicotine's plugin directory as a folder containing its PLUGININFO and __init__.py. Enable it under Nicotine's Plugins settings. Follow the plugin's current installation instructions if its layout changes.
  3. In the plugin settings, use a loopback host, its HTTP port (default 12339) and an API token. Restart/reload the plugin after changes.
  4. In VaultSeek Settings → Acquisition, select HTTP, enter the same host, API port and API token, enable Nicotine+, test and save.

The API token is not your Soulseek password. A running Nicotine process alone does not provide this HTTP API. Socket mode requires the separate NDJSON bridge. Keep conservative search intervals; peer availability and queues affect results.

Prowlarr: searches indexers

  1. Open Prowlarr and add your indexers under Indexers. Supply each indexer's own login or API key and run its Test. Include supported Audio categories.
  2. Copy Prowlarr's own key from Settings → General → Security/API Key into Plugins → Prowlarr API key, or import it with local detection.
  3. Enter its base URL, including any configured prefix. Test in VaultSeek.
  4. Enable Prowlarr plus qBittorrent for torrents and/or SABnzbd for NZBs. Save plugin settings. Set the source order in Settings → Acquisition.

Indexer accounts belong in Prowlarr. VaultSeek passes torrent/NZB results directly to the selected downloader; a Prowlarr connection by itself does not configure Usenet access or produce downloads. See Prowlarr settings.

qBittorrent: downloads torrents

  1. Open Tools → Options → Web UI and enable it. Choose a free port and a Web UI username/password. Keep authentication enabled.
  2. Enter the matching URL and credentials under Plugins → qBittorrent. Local detection can read its port and username but cannot reverse a password hash.
  3. Set category to vaultseek and optionally a dedicated download path. This path is interpreted on the downloader's computer.
  4. Test, enable qBittorrent downloads and save. Confirm a small authorized download completes and is readable by VaultSeek.

Keep seeding files in the downloader directory; let VaultSeek import completed audio. Do not place incomplete torrent files in watched Incoming. See the qBittorrent documentation.

SABnzbd: downloads Usenet articles referenced by NZBs

  1. Finish SABnzbd's wizard. In Config → Servers enter your Usenet provider's server, login, port, TLS settings and connection allowance. Test the server. Additional provider accounts belong here, not in VaultSeek.
  2. Copy the full API Key from Config → General into VaultSeek Plugins → SABnzbd. The NZB-only key is insufficient for queue/history access.
  3. In Config → Categories create vaultseek. Use that same category in VaultSeek. Give completed downloads a dedicated, accessible folder.
  4. Enter the actual URL/port/prefix, test, enable SABnzbd and Prowlarr, then save.

An indexer finds NZBs; your Usenet provider supplies their articles. Missing articles or retention limits can cause failure even when all API tests pass. See General/API settings and Categories.

NZBGet: optional Usenet downloader

SABnzbd stays the default. NZBGet is the same Prowlarr Usenet source with a different download client, not an extra search step. Choose one under Plugins → Usenet downloader. Downloads already sent keep their original client.

  1. Install NZBGet and add your Usenet server in its settings. VaultSeek does not edit nzbget.conf or start downloads while you set this up.
  2. Use the control username and password (Settings → Security), not an add-only account. Add-only logins can queue an NZB but cannot report progress, history, or cancellation.
  3. The API is JSON-RPC at http://127.0.0.1:6789/jsonrpc (HTTP Basic auth, positional parameters). Enter http://127.0.0.1:6789 in Plugins. See NZBGet’s API.
  4. Create a vaultseek category if you want one, test NZBGet, enable it, select it as the Usenet downloader, enable Prowlarr, then save.

Jellyfin and other media servers

Select the active VaultSeek library first. Open Settings → Media servers, choose the plugin, fill its fields and Save media server. Entries are associated with that library. Only one saved connection per plugin per library is exposed by this form. Configure a music library inside the server pointing to the organized Library folder, not incomplete downloads.

  • Jellyfin: sign into its dashboard as an administrator, open API Keys, create a key named VaultSeek and paste it into Token. Use the server URL, commonly http://127.0.0.1:8096. No Jellyfin cloud signup is needed. Save and verify a library refresh after importing music.
  • Emby: create a key in its administrator API Keys section; use its URL and Token. Jellyfin and Emby need different ports if both run locally.
  • Plex: use its server URL (commonly port 32400) and a Plex token from your authenticated account. This adapter defaults to section 1; this form does not yet expose a section selector. Verify that the refreshed section is your music library.
  • Navidrome / Subsonic: enter server URL and the username/password of an account allowed to access the music library. Navidrome's optional DB path must refer to a local accessible database; it is not a server address.
  • Ampache, Koel, Funkwhale, Lyrion: use the matching installed server's own authentication and endpoint documentation. These adapters expose different refresh capabilities; no common account registration flow exists. Do not assume that saving credentials validates them or enables every feature.

Reference manuals: Jellyfin, Emby, Plex token, Navidrome.

Recommendations: Last.fm and Spotify

Last.fm: sign up/sign in, open Create API account, register the application and copy its API key into Plugins → Similar music. Enable it, save, select a library and click Find recommendations now. Tune similar artists and albums per artist for a smaller Wishlist. This workflow does not need your password or shared secret and does not download music from Last.fm.

Spotify: existing apps with suitable API access can enter their client ID/secret from the developer dashboard and one playlist URL per line. This version uses Client Credentials, with no user authorization flow. Spotify's February/March 2026 Development Mode changes require Premium for the app owner and limit playlist content to playlists the authenticated user owns or collaborates on. Creating a new app or buying Premium alone does not make this integration work. A 403 can mean access restrictions, not an incorrect secret. Use Last.fm or manually add releases to the Wishlist when unavailable. Spotify migration guide.

More sources for missing music and quality upgrades

VaultSeek’s automated waterfall is Nicotine+ (Soulseek), then Usenet, then Prowlarr public torrents, then private torrents. That mix already covers most digital qualities: peer FLAC/MP3, scene/Usenet packs, and tracker rips. The items below are useful additions; they are not new automated providers unless stated. Download permitted files, extract archives outside Incoming, then copy finished audio into Incoming.

  • Bandcamp: independent releases and artist catalogs; purchased downloads offer FLAC/ALAC and MP3/AAC among other formats. Download formats.
  • Qobuz download store: purchased CD-quality and high-resolution releases, subject to territory/catalog availability. Store purchases give you files; streaming offline caches are different. Qobuz store.
  • Internet Archive / Live Music Archive: permitted live recordings, historical material and artist-approved collections. Check each item's download options and permissions; formats and recording quality vary. Live Music Archive guide.
  • Your CDs, old drives, NAS and backups: often the best source for rare editions. Rip owned CDs to lossless audio and import; search archived purchases before acquiring another copy.
  • Artist/label stores: check for direct digital purchases, particularly regional catalogs and limited releases.
  • Private indexers in Prowlarr: tracker accounts stay in Prowlarr (RED, OPS, TL, and others you are a member of). VaultSeek only consumes the private-torrent tier last by default.
  • slskd: another Soulseek client with a REST API; not wired yet. Nicotine+ remains the supported Soulseek path.
  • ListenBrainz / MusicBrainz Picard: recommendations and tagging companions, not download sources.

For compact listening, choose a good lossy original (for example MP3 320 or AAC). For archival copies, prefer lossless originals. For high-resolution collecting, require an actual high-resolution source and the desired mastering. Converting MP3 to FLAC does not restore information; a FLAC filename or high bit depth alone does not prove an upgrade. Compare edition, track count and audible quality as well as codec before replacing a release.

Recommended provider development order: local/NAS archive search, then permitted Internet Archive downloads, then slskd, then store search links and purchase import assistance. Details: the repo file docs/SOURCES.md.

What VaultSeek does

VaultSeek is a Windows desktop app for a personal music collection. It watches a drop folder, identifies songs, organizes them into a tidy Library, and can search download sources for missing tracks or better-quality copies.

Think of it in two halves:

  1. Library work — scan Incoming, fingerprint, identify, review, organize, artwork, media-server refresh.
  2. Acquisition — find gaps, queue a Wishlist, search sources, download, verify, then import back into Incoming.

VaultSeek does not replace Soulseek, Prowlarr, qBittorrent, or SABnzbd. Those programs do the actual searching and downloading. VaultSeek talks to them and then treats the finished files like anything else you dropped in Incoming.

First run

The first time you start VaultSeek with no library, the Setup wizard opens. You can reopen it anytime from Help → Setup wizard… or the Dashboard button.

The wizard asks for:

  • A library name, plus Incoming and Library folders (Staging and Archive are optional and filled in as siblings if you leave them blank).
  • Optional Nicotine+ connection (Soulseek downloads).
  • Optional Discogs and AcoustID keys (better identification and Discogs browse).
  • A quality preset (what “good enough” means for orange/green row colors and upgrades).

After Finish, follow the Dashboard Getting started checklist: confirm folders, connect a download source if you want one, then Scan Incoming.

Re-running the wizard updates the library currently selected in the top toolbar. It no longer overwrites “the first library only,” and it keeps Nicotine+ transport settings you already saved.

Day-to-day use

  1. Put audio in Incoming (or let a download finish there).
  2. File → Scan Incoming (or wait if Watch is on). Watch Jobs while hash / fingerprint / identify run.
  3. Open Review if items need a decision. Approve good matches.
  4. Browse Library / Artists / Albums. Green rows meet your quality preset; orange rows are missing or below prefs.
  5. To fill gaps: Find music → Find missing songs (or Discogs browse). Then open Wishlist and Auto-acquire, or pick a result.
  6. Parked Discogs picks sit as Wanted. On Wishlist, enable Show Wanted, then Start Wanted download.

Artists, Albums, Duplicates

Archive selected moves music to Archive and keeps it in VaultSeek. Delete album… removes the selected album's songs from the current library and its media folders, including Archive, after confirmation. Files are sent to the Windows Recycle Bin where supported; otherwise Windows may permanently delete them, as the confirmation explains. Empty album folders are removed, while unrelated files are kept. Finish library processing and cancel unfinished downloads for the album before deleting. If deletion fails, records remain for retry; any files already recycled can be recovered from the Recycle Bin.

How a download works

  1. You queue a job — Find missing songs, Discogs, or a manual album queue.
  2. Search — connected sources (Nicotine+, Prowlarr, …) look for the artist / album / track.
  3. Score — hits are ranked by how well they match title, artist, format, and your quality prefs.
  4. Download — if the score is at or above Download auto-acquire, VaultSeek starts the download. Otherwise the job waits for you to pick a result.
  5. Verify — files are never trusted automatically. VaultSeek checks they look like real audio.
  6. Import — verified files are copied into Incoming, then the normal scan → identify → organize path runs.

For missing-track jobs, VaultSeek looks for a whole album first. If no acceptable album pack is found, it falls back to a per-track search using the same quality settings.

Background wishlist searches run on the interval in Settings (0 hours = as often as Soulseek / provider rate limits allow).

Search source order (waterfall)

When more than one download source is enabled, VaultSeek tries them in a list you control. Open Settings → Wishlist & downloads → Search source order, then Save preferences.

Default order:

  1. Nicotine+ (Soulseek)
  2. Usenet (Prowlarr NZBs → SABnzbd)
  3. Prowlarr public torrents → qBittorrent
  4. Prowlarr private torrents → qBittorrent
  • Stop after the first source that finds results (on by default) — later sources are skipped once a connected source returns hits.
  • Wait after an empty source (default 15 seconds) — pause before trying the next tier when the current one found nothing.
  • A Soulseek rate-limit error does not stop later sources.
  • Turn the stop-after-first-hit box off if you want every connected source searched every time.

Enable Prowlarr / SABnzbd / qBittorrent on Plugins. Enable Nicotine+ on Settings. Reorder does not turn sources on.

Soulseek via Nicotine+

VaultSeek does not speak the Soulseek protocol itself. It talks to Nicotine+ running on the same PC.

Recommended: HTTP (api-nicotine-plus)

  1. Install and start Nicotine+. Log into Soulseek and stay connected.
  2. Install the community api-nicotine-plus plugin so Nicotine+ exposes an HTTP API (default port 12339).
  3. In VaultSeek: Settings → Wishlist & downloads.
  4. Check Enable Nicotine+ provider.
  5. Transport: HTTP (api-nicotine-plus). Host usually 127.0.0.1. HTTP API port 12339. Token if your plugin requires one.
  6. Click Test Nicotine+ connection, then Save preferences.

Advanced: NDJSON socket

Use this only if you run VaultSeek’s NDJSON companion proxy (scripts/nicotine_plus_ndjson_proxy.py) on port 22024. Set transport to VaultSeek NDJSON socket and match the NDJSON port. Keep the same HTTP plugin running behind the proxy.

Search rate limits

Soulseek can ban accounts that search too quickly (often about 30 minutes). Defaults are conservative: at least 5 seconds between searches, and at most 8 searches per minute. Raise these only if you know what you are doing.

Nicotine+ must stay running and logged in. If it is closed, Wishlist searches return nothing even when the provider is “enabled” in Settings.

Prowlarr

  1. Add audio indexers in Prowlarr (Torznab and/or Newznab).
  2. Copy the API key.
  3. In VaultSeek Plugins: enable Prowlarr, paste URL and key, set minimum torrent seeders (NZBs ignore seeders).
  4. Click Test Prowlarr.

VaultSeek searches Prowlarr’s Audio category (3000) by default.

qBittorrent (torrents)

  1. Enable the Web UI. Prefer port 8081 if SABnzbd uses 8080.
  2. In Plugins: enable qBittorrent, enter URL, username, password.
  3. Optional category vaultseek keeps VaultSeek torrents easy to spot.
  4. Optional save path; blank uses qBittorrent’s default. VaultSeek reads the completed path from the Web UI.
  5. Click Test qBittorrent.

SABnzbd (Usenet / NZB)

  1. Configure your Usenet server inside SABnzbd first.
  2. Copy the API key from Config → General.
  3. In Plugins: enable SABnzbd, paste URL and key, optional category vaultseek.
  4. Click Test SABnzbd.

When a job completes, VaultSeek imports audio from SABnzbd’s completed-folder path, then runs Incoming as usual.

Save and try one album

  2. Find music → queue one album (or promote a Wanted item).
  3. Wishlist → Auto-acquire. Watch the job: Searching → Downloading → Verifying → Completed.
  4. Check Incoming, then Library after organize.

  3. Save, then Find recommendations now.
Only public playlists work. VaultSeek does not log you into Spotify. Web API access typically requires Spotify Premium on the account that owns the developer app. A dummy redirect URI such as http://127.0.0.1:8888/callback is often required when creating the app, even though VaultSeek does not use it.

Settings page (every group)

Library

Name and folder paths for the library selected in the top toolbar. New library clears the form so you can add another collection. Scan incoming now queues a scan after the library is saved.

Reset processing

  • Clear job & review queues — deletes pending/running/failed jobs and review items. Catalog tracks and files on disk stay.
  • Clear catalog records — also removes track rows from the database. Files on disk are not deleted. Dashboard totals go back to zero. Re-scan Incoming to rebuild.

Library quality

Drives orange/green colors on Library and Albums, and “Find quality upgrades.” This is not a download-provider setting. See Quality presets.

When upgrading, prefer matching whole-album folders from the same peer — on Soulseek upgrades, prefer a folder that has the rest of the album from the same user.

Application

  • Log level — INFO for everyday use; DEBUG when something fails (applies on Save).
  • Theme — dark or light (applies on Save).
  • Discogs token — personal access token from discogs.com/settings/developers. Improves identify (genre, label, catalog) and enables Discogs browse. Restart after save.
  • AcoustID accounts + Shazamio proxies — up to three application keys (register at acoustid.org/new-applications) and optional HTTP proxies. Each key+IP is limited to about 3 lookups/sec. Proxies are also used by the Shazamio fallback (about 1 request/sec per IP). Restart after save.
  • Fingerprinting — every song, or sample a folder (faster). Sample mode only skips remaining files after enough songs match the same album, tags and filenames look right, and the file count matches the official track list. Needs an AcoustID key. Restart after save.

Open log folder / Open data folder are shortcuts. The full log viewer is System → Logs.

Data and logs

VaultSeek stores its own data under %APPDATA%\VaultSeek\ (not inside your music folders):

  • config.json — settings and API keys. Do not share this file.
  • vaultseek.db — catalog database
  • logs\vaultseek.log — everyday log
  • logs\debug.log — verbose log
  • crashes\ — crash logs if something dies
  • reports\ — generated summary files

Only one VaultSeek window should run at a time (the database is locked).

Help → About shows the exact data and log paths for this install.
